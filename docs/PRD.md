# PRD — Interview Simulator

> Продуктовые требования. Решения подтверждены владельцем 2026-09-02 (первоисточник — черновик плана MVP, удалён после разнесения по PRD/ARCHITECTURE/W200; история — wiki Orenda W200, проект P11). Этот документ — источник истины о продукте (см. AGENTS.md, «Источники истины»).

## Проблема

Подготовка к собеседованиям требует живого интервьюера: текстовые тренажёры не проверяют умение говорить, держать темп и отвечать на follow-ups; живые мок-интервью дороги и их сложно повторять регулярно. Нужен тренажёр, который при любой вакансии и грейде проводит реалистичное голосовое собеседование и даёт разбор, по которому можно готовиться.

## Решение

Веб-приложение: пользователь вставляет текст вакансии, выбирает стиль интервьюера и грейд, проходит голосовое собеседование (раунды и вопросы определяются вакансией), получает отчёт — скоринг по компетенциям, разбор каждого ответа, план подготовки и прогресс между сессиями. Настраивается под любые роли.

## Целевой пользователь

Разработчик (junior…lead), готовящийся к собеседованиям по программированию; запускает приложение локально на своей машине.

## User stories

1. Как кандидат, я вставляю текст вакансии, выбираю грейд, язык (ru/en), стиль интервьюера и число вопросов, чтобы получить интервью, сфокусированное на моей целевой позиции.
2. Как кандидат, я слышу вопросы голосом и отвечаю голосом (hold-to-talk), чтобы тренироваться в условиях, близких к реальному интервью; при отсутствии микрофона — отвечаю текстом.
3. Как кандидат, я получаю follow-up вопросы по своим ответам, чтобы интервью вскрывало слабости, а не шло по списку.
4. Как кандидат, после собеседования я получаю отчёт: общий балл, скоринг по компетенциям, разбор каждого ответа (что хорошо / что упущено / сильный ответ), вердикт и рекомендацию о найме.
5. Как кандидат, я получаю план подготовки (темы → действия) по слабым местам из отчёта.
6. Как кандидат, я вижу прогресс между сессиями (баллы по датам, средние по компетенциям, тренд), чтобы видеть динамику подготовки.
7. Как пользователь, я выбираю AI-провайдер в настройках: локальный gateway или любой облачный OpenAI-совместимый API (base_url + api_key + model) — без правки кода.
8. Как пользователь, я выбираю голос озвучки и модель распознавания в настройках.

## Scope MVP

- Сессия интервью: план (раунды: technical / behavioral / algorithms / system_design — по вакансии), 5/8/12 вопросов, cap 24 хода, три стиля интервьюера (дружелюбный / строгий FAANG / реалистичный).
- Голосовой цикл: STT (faster-whisper, локально) → LLM-ход (follow-up / следующий вопрос / завершение) → TTS (Silero, ru) по предложениям с очередью воспроизведения на фронте.
- Текстовый fallback для вопросов/ответов (без микрофона).
- Отчёт: overall_score 0–10, компетенции с комментариями, turn feedback по ходам, сильные/слабые стороны, план подготовки, вердикт + hire_recommendation (strong_yes/yes/no/strong_no).
- История сессий и агрегированный прогресс (SQLite).
- MLflow: трейсинг LLM-вызовов, сессионный run с метриками и артефактами (report.json, transcript.md).
- Настройки: провайдер (local/cloud), модель, whisper-модель, TTS-голос; смена без перезапуска.

## Non-goals (MVP)

- Аутентификация и многопользовательность (локальный single-user).
- Docker/деплой; продакшен-инфраструктура.
- Стриминговый STT/TTS (интерпретация по завершении реплики, озвучка по готовности предложений).
- Клонирование/кастомизация голосов.
- Редактор вакансий, база вакансий, интеграции с ATS/календарём.
- Мобильные приложения.
- Сохранение аудио (не персистится намеренно — приватность).

## Метрики успеха (MVP)

1. Сквозной E2E на тестовой вакансии (docs/example-vacancy.md): сессия создаётся, вопросы звучат, голосовой и текстовый ответ обрабатываются, follow-ups тематические, отчёт полный.
2. Отчёт устойчив: при единичной ошибке LLM ход деградирует без падения сессии (fallback на план/завершение); при невозможности распарсить отчёт — degraded-режим с нарративом.
3. Каждая сессия в MLflow: run с overall_score/score_*, артефакты, трейс на ход, llm_trace_id резолвится в UI.
4. Прогресс корректен минимум на двух завершённых сессиях (даты, средние, тренд).

## Ограничения и принципы

- Один кодовый путь к LLM — OpenAI SDK (base_url переключается), без SDK-обвязки на фронте (прямой fetch).
- Секреты/ключи — только через .env/настройки, не в коде, логах и артефактах (см. AGENTS.md п. 11).
- UI и промпты — на русском; язык интервью — настройка сессии.
- Локальная работа: модели/гейт — на машине пользователя; железо — RTX 3070 Ti Laptop 8 ГБ (см. wiki W200 «Окружение»).

## Открытые вопросы
