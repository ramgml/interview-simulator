## Git (инварианты)

- GitFlow: `main` (production-ready, теги `vX.Y.Z`) · `develop` (интеграция) · `task-<N>-<slug>` (задача) · `release-vX.Y.Z` (стабилизация) · `hotfix-vX.Y.Z` (фикс от тега). Детали, обоснование и схема — wiki W201.
- Прямые пуши в `main` запрещены всем, включая владельца и агентов. Форс-пуш в общие ветки запрещён.
- Любая работа — через PR: задача Orenda → ветка `task-<N>-<slug>` от `origin/develop` → PR → ревью → мерж `--no-ff`.
- Обратный мерж `release-*` / `hotfix-*` в `develop` после финиша обязателен (потеря обратного мержа = потерянный фикс).
- Коммиты — conventional: `feat|fix|docs|chore|refactor|test`, scope `(T<N>)` с номером задачи Orenda.
- Одна задача = одна ветка = один PR; мелкие батчи, commit early/often.

## Агенты (инварианты)

- Параллельные агенты не шарат рабочую копию: worktree на задачу (`.worktrees/task-<N>-<slug>`), общий `.git`.
- Изоляция ресурсов: у каждого worktree свои `data/` (SQLite, MLflow — просто файлы) и свои порты (актуальный реестр портов — wiki W200, раздел «Окружение»). Порты и пути данных не хардкодить вне конфига.
- До пуша — зелёные локальные гейты: `ruff`, `tsc --noEmit`; после появления тест-набора — `pytest`. Тяжёлые проверки — на `release-*`, не в цикле агента.
- Ревью синхронное: PR готов → ревью сразу; не копить открытые PR (конфликты между параллельными ветками).

## Безопасность и данные (инварианты)

- Секреты: `.env` не коммитится; API-ключи не попадают в код, логи, MLflow-артефакты и промпты.
- Не коммитятся: `data/`, `.venv/`, `node_modules/`, `.next/`, `*.db*`.
- Аудио пользователей не персистится (решение PRD: в отчёте только текст) — не добавлять сохранение аудио без явного решения владельца.
- Продуктовый язык: UI и промпты — на русский; язык интервью — настройка сессии. Изменение — через PRD, не через код.

## Код: как писать (инварианты)

- Следуй существующему стилю файла/модуля; вторая конвенция рядом с существующей запрещена. Сомневаешься — посмотри соседний код, а не придумывай.
- Минимальный дифф: меняй только то, что требует задача. Посторонние рефакторы, переформатирования, «попутные» чистки — отдельная задача, не этот PR.
- Контракты (API-схемы, LLM-протоколы, JSON-форматы) — из `docs/ARCHITECTURE.md`; менять их можно только вместе с документацией в том же PR.
- Ошибки — наружу типизированно (`InterviewError`, `EmptyTranscript` → осмысленный HTTP-код и текст, контракт ошибок — `docs/ARCHITECTURE.md` §API), не глотать и не логировать молча. Никаких пустых `except:` / `catch {}`.
- Секреты и конфиг — только через `config.py` (pydantic-settings, `.env`). Никаких литералов URL/портов/ключей в коде (см. «Безопасность и данные»).
- Каждая новая наблюдаемая возможность — тест (pytest для бэка, поведение, не «плейсхолдер»). Тест не должен зависеть от живого LLM: стабы (`FakeClient`).
- Prompts — константы в коде модуля, на русском (точные формулировки PLAN/TURN/EVAL — `docs/ARCHITECTURE.md` §Интервьюер/§Оценщик), без интерполяции секретов; изменения промпта = изменение наблюдаемого поведения = тест/скрин в PR.
- Зависимости добавлять только при необходимости задачи; версию фиксировать в `pyproject.toml`/`package.json`, не «latest» (остальное — раздел «Зависимости»).
- Фронт: только shadcn-примитивы (`components/ui/*`); сырые `<button>/<input>/<select>` и самописные модалки (`fixed inset-0`) в `features`-коде запрещены. Тексты UI — на русском (см. «Безопасность и данные»).

## Код: как НЕ писать (запреты)

- Не оставляй заглушек: `TODO`, `pass # implement later`, фиктивные дефолты «пока так». Недоделанное = задача не готова к ревью.
- Не расширяй скоуп: не добавляй фичи/эндпоинты/поля «на будущее», которых нет в постановке задачи и `docs/PRD.md`.
- Не подавляй симптом: отключение теста, ослабление типа (`any`), удаление проверки, чтобы «зелёненькое» — запрещено. Починяй причину.
- Не пиши данные/состояние в код: мок-файлы, захардкоженные сиды с реальными данными, коммиты `data/*.db`. Фикстуры тестов — синтетические.
- Не обходи гейты: `--no-verify`, правки хуков ради прохода, комментирование упавших проверок — запрещены (см. «Агенты»).
- Не трогай чужие worktree/чекауты (см. «Агенты»); не мержи свой PR сам.

## Готовность (DoD-инвариант)

- Задача готова к ревью, только если: (а) заявленное поведение подтверждено доказательствами — вывод команд, curl/Swagger-прогоны, скриншоты UI; слова «implemented/works» не доказательство; (б) изменённый наблюдаемый контракт покрыт тестом или ручной проверкой, приложенной к PR; (в) локальные гейты из «Агентов» зелёные. Ручной сквозной сценарий — по чеклисту «Верификация MVP» в `docs/ARCHITECTURE.md`. PR без доказательств — на доработку, независимо от качества кода.

## Наблюдаемость (инварианты)

- Логи структурные, с `session_id`/`turn_idx` где уместно; в логах нет секретов и пользовательского аудио/текста целиком. Сообщения исключений: логи и код — на английском, тексты ошибок для UI — на русском (см. «Безопасность и данные»).
- `print()` для отладки запрещён — только структурный логгер; отладочные эндпоинты (`/api/debug/*`) не уходят дальше `develop`-отладки и не документируются как публичный API.

## Производительность и GPU (инварианты)

- Whisper/TTS — ленивые синглтоны; инициализация модели на каждый запрос запрещена. Тяжёлые синхронные шаги (STT, TTS, LLM-ход) не блокируют event loop: `run_in_executor`/пул.
- VRAM — общий ресурс машины (см. W200): не держать загруженными неиспользуемые модели; добавляя GPU-шаг, проверь профиль памяти и fallback на CPU — изоляция из «Агентов» не должна ломаться.

## Схема БД и совместимость API (инварианты)

- Схема БД меняется только аддитивно (новые таблицы/колонки, nullable); переименования/удаления/смены типов — только по явному решению владельца, отдельной задачей с миграцией.
- `/api/*` — контракт фронта: не переименовывать поля/эндпоинты и не менять семантику ответов молча; любая смена — синхронно `docs/ARCHITECTURE.md` + фронт в том же PR (см. «Код: как писать»).

## Тесты (инварианты)

- Тесты детерминированы: без sleep, сети, живого LLM (стаб `FakeClient`), реального `data/` — временная директория в фикстурах. Один тест защищает один контракт; тест на «как написано в коде», а не на поведение, — не тест.

## Зависимости (инварианты)

- Lockfiles (`uv.lock`, `package-lock.json`) коммитятся; воспроизводимая установка — только через них.
- Добавляемая/обновляемая зависимость: (а) актуально и сопровождается — deprecated-пакеты и пакеты без релизов 12+ месяцев запрещены (если альтернативы нет — явное решение владельца в задаче); (б) без известных критических уязвимостей в закреплённой версии; (в) добавление/обновление — отдельным изменением в рамках задачи, не «попутно»; причина — в описании PR.
- Встроенная альтернатива stdlib/платформы предпочтительнее новой зависимости; снятие зависимости — приветствуется, отдельным коммитом `chore(deps)` с прогоном тестов.

## Коммуникация воркера (инвариант)

- PR-описание по схеме: что сделано / доказательства (см. «Готовность») / как проверить. Проблема в постановке (противоречие, недостающие данные, невыполнимый DoD) — не додумывать: остановиться и эскалировать владельцу/PM через задачу.

## Git-гигиена (инварианты)

- Локальный `develop` — fast-forward-only зеркало `origin/develop`. Прямых коммитов в локальный `develop` нет ни у кого; синк — явное действие в main checkout: `git fetch origin && git merge --ff-only origin/develop`. Если fast-forward невозможен — в локальном `develop` застряли «осиротевшие» коммиты: сначала доставить их через PR, затем синк (не откручивать назад).
- Прямые пуши в `develop` запрещены всем, включая владельца и агентов (как в `main`). Единственный путь в `develop` — мерж PR `--no-ff` владельцем.
- База ветки задачи — `origin/develop` сразу после `git fetch origin`, никогда локальный `develop`: локальная копия отстаёт с каждым смерженным PR, а устаревшая база перетаскивает уже смерженную работу в ревью конфликтами.
- Main checkout read-only для агентов: правки файлов, `git checkout`/`reset`/`clean`/`restore` в рабочей копии, которую агент не создавал, запрещены; читать файлы — можно. Исключения — синк `develop` и уборка смерженного потока (следующий пункт).
- Уборка потока — сразу после мержа PR: `git worktree remove .worktrees/task-<N>-<slug>` и `git branch -d task-<N>-<slug>`; незакоммиченный хвост перед уборкой не оставлять (незакоммиченное ничем не защищено). Периодически — `git worktree prune`.
