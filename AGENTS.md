## Git (инварианты)

1. GitFlow: `main` (production-ready, теги `vX.Y.Z`) · `develop` (интеграция) · `task-<N>-<slug>` (задача) · `release-vX.Y.Z` (стабилизация) · `hotfix-vX.Y.Z` (фикс от тега). Детали, обоснование и схема — wiki W201.
2. Прямые пуши в `main` запрещены всем, включая владельца и агентов. Форс-пуш в общие ветки запрещён.
3. Любая работа — через PR: задача Orenda → ветка `task-<N>-<slug>` от `origin/develop` → PR → ревью → мерж `--no-ff`.
4. Обратный мерж `release-*` / `hotfix-*` в `develop` после финиша обязателен (потеря обратного мержа = потерянный фикс).
5. Коммиты — conventional: `feat|fix|docs|chore|refactor|test`, scope `(T<N>)` с номером задачи Orenda.
6. Одна задача = одна ветка = один PR; мелкие батчи, commit early/often.

## Код: как писать (инварианты)

15. Следуй существующему стилю файла/модуля; вторая конвенция рядом с существующей запрещена. Сомневаешься — посмотри соседний код, а не придумывай.
16. Минимальный дифф: меняй только то, что требует задача. Посторонние рефакторы, переформатирования, «попутные» чистки — отдельная задача, не этот PR.
17. Контракты (API-схемы, LLM-протоколы, JSON-форматы) — из `docs/ARCHITECTURE.md`; менять их можно только вместе с документацией в том же PR.
18. Ошибки — наружу типизированно (`InterviewError`, `EmptyTranscript` → осмысленный HTTP-код и текст, контракт ошибок — `docs/ARCHITECTURE.md` §API), не глотать и не логировать молча. Никаких пустых `except:` / `catch {}`.
19. Секреты и конфиг — только через `config.py` (pydantic-settings, `.env`). Никаких литералов URL/портов/ключей в коде (см. п. 8).
20. Каждая новая наблюдаемая возможность — тест (pytest для бэка, поведение, не «плейсхолдер»). Тест не должен зависеть от живого LLM: стабы (`FakeClient`).
21. Prompts — константы в коде модуля, на русском (точные формулировки PLAN/TURN/EVAL — `docs/ARCHITECTURE.md` §Интервьюер/§Оценщик), без интерполяции секретов; изменения промпта = изменение наблюдаемого поведения = тест/скрин в PR.
22. Зависимости добавлять только при необходимости задачи; версию фиксировать в `pyproject.toml`/`package.json`, не «latest» (остальное — раздел «Зависимости», пп. 38–40).
23. Фронт: только shadcn-примитивы (`components/ui/*`); сырые `<button>/<input>/<select>` и самописные модалки (`fixed inset-0`) в `features`-коде запрещены. Тексты UI — на русском (п. 14).

## Код: как НЕ писать (запреты)

24. Не оставляй заглушек: `TODO`, `pass # implement later`, фиктивные дефолты «пока так». Недоделанное = задача не готова к ревью.
25. Не расширяй скоуп: не добавляй фичи/эндпоинты/поля «на будущее», которых нет в постановке задачи и `docs/PRD.md`.
26. Не подавляй симптом: отключение теста, ослабление типа (`any`), удаление проверки, чтобы «зелёненькое» — запрещено. Починяй причину.
27. Не пиши данные/состояние в код: мок-файлы, захардкоженные сиды с реальными данными, коммиты `data/*.db`. Фикстуры тестов — синтетические.
28. Не обходи гейты: `--no-verify`, правки хуков ради прохода, комментирование упавших проверок — запрещены (п. 9).
29. Не трогай чужие worktree/чекауты (п. 7); не мержи свой PR сам.

## Агенты (инварианты)

7. Параллельные агенты не шарат рабочую копию: worktree на задачу (`.worktrees/task-<N>-<slug>`), общий `.git`.
8. Изоляция ресурсов: у каждого worktree свои `data/` (SQLite, MLflow — просто файлы) и свои порты (актуальный реестр портов — wiki W200, раздел «Окружение»). Порты и пути данных не хардкодить вне конфига.
9. До пуша — зелёные локальные гейты: `ruff`, `tsc --noEmit`; после появления тест-набора — `pytest`. Тяжёлые проверки — на `release-*`, не в цикле агента.
10. Ревью синхронное: PR готов → ревью сразу; не копить открытые PR (конфликты между параллельными ветками).

## Безопасность и данные (инварианты)

11. Секреты: `.env` не коммитится; API-ключи не попадают в код, логи, MLflow-артефакты и промпты.
12. Не коммитятся: `data/`, `.venv/`, `node_modules/`, `.next/`, `*.db*`.
13. Аудио пользователей не персистится (решение PRD: в отчёте только текст) — не добавлять сохранение аудио без явного решения владельца.
14. Продуктовый язык: UI и промпты — на русский; язык интервью — настройка сессии. Изменение — через PRD, не через код.

## Готовность (DoD-инвариант)

30. Задача готова к ревью, только если: (а) заявленное поведение подтверждено доказательствами — вывод команд, curl/Swagger-прогоны, скриншоты UI; слова «implemented/works» не доказательство; (б) изменённый наблюдаемый контракт покрыт тестом или ручной проверкой, приложенной к PR; (в) гейты п. 9 зелёные. Ручной сквозной сценарий — по чеклисту «Верификация MVP» в `docs/ARCHITECTURE.md`. PR без доказательств — на доработку, независимо от качества кода.

## Наблюдаемость (инварианты)

31. Логи структурные, с `session_id`/`turn_idx` где уместно; в логах нет секретов (п. 11) и пользовательского аудио/текста целиком. Сообщения исключений: логи и код — на английском, тексты ошибок для UI — на русском (п. 14).
32. `print()` для отладки запрещён — только структурный логгер; отладочные эндпоинты (`/api/debug/*`) не уходят дальше `develop`-отладки и не документируются как публичный API.

## Производительность и GPU (инварианты)

33. Whisper/TTS — ленивые синглтоны; инициализация модели на каждый запрос запрещена. Тяжёлые синхронные шаги (STT, TTS, LLM-ход) не блокируют event loop: `run_in_executor`/пул.
34. VRAM — общий ресурс машины (см. W200): не держать загруженными неиспользуемые модели; добавляя GPU-шаг, проверь профиль памяти и fallback на CPU (п. 8 — изоляция не должна ломаться).

## Схема БД и совместимость API (инварианты)

35. Схема БД меняется только аддитивно (новые таблицы/колонки, nullable); переименования/удаления/смены типов — только по явному решению владельца, отдельной задачей с миграцией.
36. `/api/*` — контракт фронта: не переименовывать поля/эндпоинты и не менять семантику ответов молча; любая смена — синхронно `docs/ARCHITECTURE.md` + фронт в том же PR (п. 17).

## Тесты (инварианты)

37. Тесты детерминированы: без sleep, сети, живого LLM (стаб `FakeClient`), реального `data/` — временная директория в фикстурах. Один тест защищает один контракт; тест на «как написано в коде», а не на поведение, — не тест.

## Зависимости (инварианты)

38. Lockfiles (`uv.lock`, `package-lock.json`) коммитятся; воспроизводимая установка — только через них.
39. Добавляемая/обновляемая зависимость: (а) актуально и сопровождается — deprecated-пакеты и пакеты без релизов 12+ месяцев запрещены (если альтернативы нет — явное решение владельца в задаче); (б) без известных критических уязвимостей в закреплённой версии; (в) добавление/обновление — отдельным изменением в рамках задачи, не «попутно»; причина — в описании PR.
40. Встроенная альтернатива stdlib/платформы предпочтительнее новой зависимости; снятие зависимости — приветствуется, отдельным коммитом `chore(deps)` с прогоном тестов.

## Коммуникация воркера (инвариант)

41. PR-описание по схеме: что сделано / доказательства (п. 30) / как проверить. Проблема в постановке (противоречие, недостающие данные, невыполнимый DoD) — не додумывать: остановиться и эскалировать владельцу/PM через задачу.
